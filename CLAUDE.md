# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Promise" — a 2D side-scrolling puzzle-platformer built in **Unity 6000.5.3f1** with **URP 17** (2D renderer), Cinemachine 2, 2D Animation/PSD Importer, SpriteShape, and DragonBones for some character rigs. Not a git repository. There are no test assemblies and no build scripts; everything is driven from the Unity Editor.

## Building / running

- Open the project in Unity Hub with editor 6000.5.3f1 and press Play from `Assets/Scenes/MainMenu.unity` (build index 0). Scene order matters — see below.
- Headless build (no custom build method exists, so use the default player build):
  `"<Unity 6000.5.3f1>/Editor/Unity.exe" -batchmode -quit -projectPath . -buildWindows64Player Build/Promise.exe -logFile -`
- Compile-check C# without the Editor is not set up; `Promise-1-pk.slnx` / `.csproj` files are generated by Unity (IDE packages for VS, Rider and VS Code are installed). Edit `.cs` files, then let Unity recompile.
- `com.unity.test-framework` is installed but there are no tests.

## Code layout

All game code is in `Assets/Script/` and compiles into the default `Assembly-CSharp` (no asmdef). Only `Assets/AttrPk/` (the **MyBox** attribute library, `MyBox.asmdef`) has its own assembly. Everything else under `Assets/` (DragonBones, Foliage2D, TreePack, sound packs, TextMesh Pro, Tarodev controller assets) is third‑party content — avoid editing it.

`Assets/Script/` contains two generations of code that coexist:

1. **Top-level scripts (the project's own code, "Pk" suffix in places)** — the current gameplay:
   - `PlayerMovement` reads legacy Input Manager axes (`Horizontal`, `Space` to jump) in `Update` and forwards to `PlayerController.Move()` in `FixedUpdate`. `PlayerController` is a Rigidbody2D controller (SmoothDamp velocity, coyote time, ground check via `OverlapCircleAll` on a layer mask, sprite flip via negative `localScale.x`). It also raycasts forward and sets `PlayerMovement._freezeLeft/_freezeRight` when hitting objects tagged `Blockable`.
   - `PushableAndPullable` — hold `Fire1` to attach a `FixedJoint2D` to a box on `boxMask`; box mass is toggled 1 ↔ 500 to make it draggable vs. immovable.
   - `Platform` — one component with a `PlatformType` enum (Moving / Appearing / Falling / Raising); fields are shown per-type via MyBox `[ConditionalField]`. Activated by setting `On`, typically from `SwitchTrigger`. Moving platforms parent the Player on collision.
   - `LevelChanger` — `DontDestroyOnLoad` singleton that drives scene transitions: `FadeToLevel(i)` fires the `FadeOut` animator trigger, and the fade animation calls `OnFadeComplete()` via an animation event to actually `LoadScene`. `FadeToNextLevel()` advances by build index and wraps to 0. `LoadCurrentLevel()` reloads immediately (used for death/restart).
   - `MenuController` / `MenuButton` — keyboard-navigated menus (vertical axis changes `index`; buttons react to their index). Menu actions go through `LevelChanger`.
   - `GameManagerPk` — Escape-key pause menu using the static `GameManagerPk._isPaused` flag, which `PlayerMovement` checks. Only present in `Level8`.

2. **`Assets/Script/TB/`** — an imported platformer kit (`NewPlayer : PhysicsObject`, `EnemyBase`/`Walker`/`Flyer`, dialogue, HUD, parallax, collectables, `SceneLoadTrigger`). `TB/Core/GameManager.cs` has been modified: its trigger collider acts as a kill zone that calls `LevelChanger.LoadCurrentLevel()`.

### Which pieces are actually used in scenes

- `Prefabs/GameManager.prefab` (in every level) = `LevelChanger` + TB `GameManager` (kill-zone trigger, audio, HUD refs). Many scripts locate it with `FindObjectOfType<LevelChanger>()`.
- `Prefabs/Blacky .prefab` (note the trailing space in the filename) is the main player: `PlayerMovement` + `PlayerController` + `PlayerAnimationController`. It is rigged with **DragonBones** (`Armature` child, `UnityArmatureComponent`, data `Assets/Blacky/BlackyP&P/Player_Data.asset`, animations `Idle`, `IdleStraight`, `Run`, `Jump`, `Push`, `Pull`) and has no Unity `Animator`. `PlayerMovement.anim` must stay typed as `PlayerAnimationController`. The `Arloo` animator controller belongs to the TB `Player.prefab` only.
- `Prefabs/Whitey.prefab` is a DragonBones-rigged character (`UnityArmatureComponent`) with `fader`.
- `Prefabs/Player.prefab` is the TB `NewPlayer`, still placed in `MountainLevel1`, `MountainLevel2` and `Test`.

## Scenes and level flow

Build order lives in `ProjectSettings/EditorBuildSettings.asset`: `MainMenu` → `Mountain/MountainLevel1–4, 6, 7` → `Level4`, `Level5`, `Level7`. `MountainLevel5`, `Mountain/0` and `ThankYouScene` are disabled; `Level8` and `Test` aren't in the build. Because progression is by build index (`FadeToNextLevel`, `FadeToLevel(1)` for New Game, `FadeToLevel(0)` for main menu), reordering or enabling/disabling scenes changes gameplay flow.

## Conventions and gotchas

- Tags used by code: `Player`, `Blockable`. Physics queries depend on layer masks set in the Inspector (`m_WhatIsGround`, `boxMask`).
- Input uses the legacy `UnityEngine.Input` manager (not the Input System package).
- Game code uses the Unity 6 APIs: `Rigidbody2D.linearVelocity` (not `velocity`), `bodyType` (not `isKinematic`), `FindAnyObjectByType` (not `FindObjectOfType`). `velocity` on `PhysicsObject`/`NewPlayer`/`Walker` is the kit's own field, not a Rigidbody property. Unity 6.5 turns several old APIs into compile *errors* (`GetInstanceID`, `Selection.activeInstanceID`, `EndNameEditAction`), and an error in any script puts the Editor in Safe Mode; MyBox, DragonBones and Foliage2D have been patched for this (EntityId APIs behind `#if UNITY_6000_3_OR_NEWER` where an old path is kept).
- Verify changes with a headless player build: `Unity.exe -batchmode -quit -nographics -projectPath . -buildWindows64Player <out>/Promise.exe -logFile <log>`, then grep the log for `error CS` / `Build Finished, Result`.
- Serialized field names (`m_JumpForce`, `_runSpeed`, `On`, etc.) are referenced by scene/prefab YAML — renaming them loses Inspector values unless you add `[FormerlySerializedAs]`.
- Behaviour wiring often lives in scene/prefab data (UnityEvents on buttons, animation events like `OnFadeComplete`), so grep `.unity`/`.prefab`/`.anim` files by script GUID (from the `.cs.meta`) or method name before removing anything.
- `Assets/Script/._PhysicsObject.cs` is a macOS resource-fork artifact, not real code.
