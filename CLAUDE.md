# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Promise" — a 2D side-scrolling puzzle-platformer (Limbo-style silhouettes; a love story: Blacky, in a coma, chases Whitey through a dark coma world; each level ends when Blacky reaches Whitey and she fades away). Built in **Unity 6000.5.3f1** with **URP 17** (2D renderer), Cinemachine 2, 2D Animation/PSD Importer, SpriteShape, Timeline, and DragonBones for the character rigs. Target platforms: PC and consoles.

Git repo (`origin` = GitHub `PraveenUnitydev/Promise`). `main` holds the original 8-year-old project including all old level scenes; active work happens on `dev`. Levels are being rebuilt from scratch — look at `main` for the old layouts.

## Building / running

- Open the project in Unity Hub with editor 6000.5.3f1 and press Play from `Assets/_Promise/Scenes/Menus/MainMenu.unity` (build index 0). `Scenes/Dev/Sandbox.unity` is the old test scene (Blacky, Whitey, a switch and platforms); `Scenes/Dev/SystemsTest.unity` is a greybox that exercises every gameplay system.
- Verify changes with a headless player build (no custom build method exists), then grep the log for `error CS` / `Build Finished, Result`:
  `"<Unity 6000.5.3f1>/Editor/Unity.exe" -batchmode -quit -nographics -projectPath . -buildWindows64Player <out>/Promise.exe -logFile <log>`
  The Editor must be closed for this, or it fails because the project is locked.
- Scene/prefab setup can be scripted headlessly: a temporary `Assets/Editor/*.cs` static method run with `Unity.exe -batchmode -quit -projectPath . -executeMethod Class.Method` (omit `-nographics` to render review screenshots with a temporary camera into a RenderTexture). Delete the script afterwards.
- `.csproj` / `.slnx` files are generated by Unity and git-ignored. `com.unity.test-framework` is installed but there are no tests.

## Folder layout

- `Assets/_Promise/` — everything that belongs to the game:
  - `Scripts/` — `Player/`, `Characters/`, `Level/` (+ `Level/Signals/`), `Core/`, `UI/`, `Camera/`. All compile into the default `Assembly-CSharp` (no asmdef).
  - `Prefabs/` — `Characters/` (Blacky, Whitey), `Level/` (Box, pillars, mounts, broken stone, Checkpoint, KillZone, PressurePlate, Lever, Gate), `Systems/` (GameManager), `UI/`.
  - `Scenes/` — `Menus/`, `Dev/`; new levels go in `Scenes/Levels/`.
  - `Art/` — `Characters/` (DragonBones exports), `Environment/`, `UI/`, `Fonts/`, `Shaders/` (`SpriteDissolve.shader`, Whitey's fade).
  - `Animations/` (`UI/`, `Props/`), `Audio/`, `Effects/` (dust/land/launch particles).
  - `Settings/Rendering/` (URP pipeline asset, 2D renderer, global settings, volume profiles) and `Settings/Physics2D/` (physics materials).
- Third-party, avoid editing: `Assets/DragonBones/`, `Assets/Foliage2D/` (hardcodes its own `Assets/Foliage2D/Gizmos` path — don't move it; its inspector's sorting-layer dropdown is patched), `Assets/MyBox/` (MyBox attribute library, own `MyBox.asmdef`), `Assets/TextMesh Pro/`.

## Gameplay code

### Player
- `PlayerMovement` reads input from `GameInput` in `Update` (with a jump buffer), drives animation, and forwards to `PlayerController.Move(move, crouch, jump, jumpHeld)` in `FixedUpdate`, which returns true when a jump starts. While grabbing a box it scales speed by `_grabSpeedMultiplier`, blocks jumping and sets `PlayerController.m_LockFacing`.
- `PlayerController` is a Rigidbody2D controller (SmoothDamp velocity with separate air smoothing, coyote time, jump lockout, variable jump height via `m_JumpCutMultiplier`, ground check via `OverlapCircleAll` on `m_WhatIsGround` = Ground + Platform + Pushable, flip via negative `localScale.x`). `ResetMotion()` clears velocity and jump state (used by respawn). It raycasts forward and sets `PlayerMovement._freezeLeft/_freezeRight` when facing an object tagged `Blockable` (shows Idle instead of Run).
- `PlayerAnimationController` wraps the DragonBones `UnityArmatureComponent` (`Idle`, `IdleStraight`, `Run`, `Jump`, `Push`, `Pull`). Blacky has no Unity `Animator`; `PlayerMovement.anim` must stay typed as `PlayerAnimationController`. The air pose is held from take-off to landing and the single `Jump` clip is scrubbed by vertical speed (`Jump(vy)`). Write `DragonBones.AnimationState` fully qualified (it clashes with `UnityEngine.AnimationState`).
- `PushableAndPullable` (on Blacky) — hold Grab next to or into a box on `boxMask` (Pushable) while grounded to attach a `FixedJoint2D`; box mass toggles 1 ↔ 500. Releases on letting go, leaving the ground, or respawn.

### Respawn and checkpoints
- `RespawnManager` is created automatically in any scene containing a `PlayerMovement` (don't place it). Level start is the first checkpoint. `KillPlayer()` freezes the player, fades out (`ScreenFader`), rewinds every `IResettable`, moves the player to the last checkpoint and fades in. The scene is never reloaded.
- `IResettable`: `CaptureState` on checkpoint / level start, `RestoreState` on respawn. Implemented by `ResettableBody` (put on boxes and other movable props), `Platform`, all `SignalReceiver`s, `SignalSwitch`, `PushableAndPullable`. Any new stateful puzzle object must implement it, or it won't rewind.
- `Checkpoint` — trigger; optional `_spawnPoint` (Blacky's feet). `KillZone` — trigger or solid collider that calls `RespawnManager.KillPlayer()` (falls back to reloading the scene if there is no manager).

### Signals (switches → targets)
- `Scripts/Level/Signals/`: a `SignalSource` drives a list of `SignalReceiver` targets (wired in the Inspector) plus optional one-off UnityEvents. Receivers combine several sources with `Logic` Any/All and can invert.
- `SignalSwitch` (source; same GUID as the old `SwitchTrigger`): modes OneShot / Toggle / Hold / Timed, `_activators` layer mask (default Player + Pushable), `_requireInteract` for levers (press Grab inside the area), `_showWhenOn` objects and an optional animator bool (`Switch_On`). Occupancy is polled each physics step with `Collider2D.Overlap`, not enter/exit events, so it survives respawn teleports.
- Receivers: `Platform` (sets `On`), `SignalMover` (slides by `_openOffset`: doors, gates, lifts; can carry the player), `SignalToggle` (shows/hides objects), `SignalEvents` (UnityEvents; not rewound).
- Ready-made prefabs in `Prefabs/Level/`: `Checkpoint`, `KillZone`, `PressurePlate` (Hold), `Lever` (Toggle + interact), `Gate` (SignalMover). Triggers sit on the Ignore Raycast layer.

### Other
- `Platform` — one component with a `PlatformType` enum (Moving / Appearing / Falling / Raising); fields shown per type via MyBox `[ConditionalField]`. Moving platforms parent the Player on collision. Falling platforms trigger on contact.
- `LevelChanger` — one per level (in GameManager.prefab, on a child Canvas): `FadeToLevel(i)` fires the `FadeOut` animator trigger and the fade animation calls `OnFadeComplete()` via an animation event to `LoadScene`. `FadeToNextLevel()` advances by build index and wraps to 0. `LoadCurrentLevel()` reloads immediately (menu Restart).
- `fader` (on Whitey) — on Player trigger: fades to the next level, dissolves Whitey via a per-renderer `MaterialPropertyBlock` (`_Fade`) and freezes the player. Whitey's material uses `Promise/Sprite Dissolve` (hand-written URP 2D unlit shader; the old Dissolve shader graph stopped producing a usable pass in Unity 6.5 and rendered her invisible).
- `MenuController` / `MenuButton` / `AnimatorFunctionsPk` — menus. `GameManagerPk` — pause menu with static `_isPaused` (checked by `PlayerMovement`); it compares the scene name to `"MainMenu"`, so don't rename that scene.
- `Prefabs/Systems/GameManager.prefab` (in every level) = `LevelChanger` + `KillZone` edge on the root + `Blockables` walls (child) + pause menu UI.

## Scenes and level flow

Build order (`ProjectSettings/EditorBuildSettings.asset`): `MainMenu`, `Dev/Sandbox`, `Dev/SystemsTest`. Progression is by build index (`FadeToNextLevel`, `FadeToLevel(1)` for New Game, `FadeToLevel(0)` for the main menu), so reordering scenes changes gameplay flow. A level is one scene of several puzzle rooms joined seamlessly with a checkpoint per room; reaching Whitey ends it.

## Conventions and gotchas

- Tags used by code: `Player`, `Blockable`, `Pushable`. Layers: `Ignore Raycast` (2, triggers), `Ground` (8), `Player` (9), `Platform` (10), `Pushable` (11), `Blockable` (12).
- Sorting layers: `Background` → `MidGround` (level geometry, foliage behind characters) → `Player` (Blacky, Whitey; set through `UnityArmatureComponent.sortingLayerName` so every slot follows) → `Foreground` (foliage and fog in front). YAML stores sorting layer IDs as signed ints (MidGround = -518394107, Player = -834378003) while TagManager lists them unsigned; they are the same layers.
- All input goes through `Scripts/Core/GameInput.cs` (Input System 1.19, actions defined in code with keyboard + gamepad bindings: Move, Jump, Grab, Pause, Peek, Navigate, Submit, Cancel). Never call `UnityEngine.Input` from game code. Active Input Handling is "Both" only because MyBox and the menu EventSystem (`StandaloneInputModule`) still use the legacy manager.
- Use Unity 6 APIs: `Rigidbody2D.linearVelocity` (not `velocity`), `bodyType` (not `isKinematic`), `FindAnyObjectByType` (not `FindObjectOfType`). Unity 6.5 turns several old APIs into compile *errors* (`GetInstanceID`, `Selection.activeInstanceID`, `EndNameEditAction`), and an error in any script puts the Editor in Safe Mode; MyBox, DragonBones and Foliage2D have been patched for this.
- Serialized field names (`m_JumpForce`, `_runSpeed`, `On`, etc.) are referenced by scene/prefab YAML — renaming them loses Inspector values unless you add `[FormerlySerializedAs]`.
- Behaviour wiring often lives in scene/prefab data (UnityEvents on buttons, animation events like `OnFadeComplete`), so grep `.unity`/`.prefab`/`.anim` files by script GUID (from the `.cs.meta`) or method name before removing anything. Always move assets together with their `.meta` files (`git mv` both) to keep GUIDs.
- `Art/Environment/Sprites/Square.png` has a non-centred pivot; offset its sprite when building greybox blocks.
- Known broken references inherited from the old project: `Sandbox.unity` lighting settings asset, the sprite on `Prefabs/UI/WhiteFade.prefab`, and one clip in `Animations/UI/LoadingScreen.controller`.
