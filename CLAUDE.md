# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Promise" — a 2D side-scrolling puzzle-platformer (Limbo-style silhouettes; a love story: Blacky, in a coma, chases Whitey through a dark coma world; each level ends when Blacky reaches Whitey and she fades away). Built in **Unity 6000.5.3f1** with **URP 17** (2D renderer), Cinemachine 2, 2D Animation/PSD Importer, SpriteShape, Timeline, and DragonBones for the character rigs. Target platforms: PC and consoles.

Git repo (`origin` = GitHub `PraveenUnitydev/Promise`). `main` holds the original 8-year-old project including all old level scenes; active work happens on `dev`. Levels are being rebuilt from scratch — look at `main` for the old layouts.

## Building / running

- Open the project in Unity Hub with editor 6000.5.3f1 and press Play from `Assets/_Promise/Scenes/Menus/MainMenu.unity` (build index 0). `Assets/_Promise/Scenes/Dev/Sandbox.unity` is a test scene with Blacky, Whitey, a switch and platforms.
- Verify changes with a headless player build (no custom build method exists), then grep the log for `error CS` / `Build Finished, Result`:
  `"<Unity 6000.5.3f1>/Editor/Unity.exe" -batchmode -quit -nographics -projectPath . -buildWindows64Player <out>/Promise.exe -logFile <log>`
  The Editor must be closed for this, or it fails because the project is locked.
- `.csproj` / `.slnx` files are generated by Unity and git-ignored. `com.unity.test-framework` is installed but there are no tests.

## Folder layout

- `Assets/_Promise/` — everything that belongs to the game:
  - `Scripts/` — `Player/`, `Characters/`, `Level/`, `Core/`, `UI/`, `Camera/`. All compile into the default `Assembly-CSharp` (no asmdef).
  - `Prefabs/` — `Characters/` (Blacky, Whitey), `Level/` (Box, pillars, mounts, broken stone), `Systems/` (GameManager), `UI/`.
  - `Scenes/` — `Menus/`, `Dev/`; new levels go in `Scenes/Levels/`.
  - `Art/` — `Characters/` (DragonBones exports), `Environment/`, `UI/`, `Fonts/`, `Shaders/` (Dissolve shader graph used by Whitey's fade).
  - `Animations/` (`UI/`, `Props/`), `Audio/`, `Effects/` (dust/land/launch particles).
  - `Settings/Rendering/` (URP pipeline asset, 2D renderer, global settings, volume profiles) and `Settings/Physics2D/` (physics materials).
- Third-party, avoid editing: `Assets/DragonBones/`, `Assets/Foliage2D/` (hardcodes its own `Assets/Foliage2D/Gizmos` path — don't move it), `Assets/MyBox/` (MyBox attribute library, own `MyBox.asmdef`), `Assets/TextMesh Pro/`.

## Gameplay code

- `PlayerMovement` reads legacy Input Manager axes (`Horizontal`, `Space` to jump) in `Update`, drives animation, and forwards to `PlayerController.Move()` in `FixedUpdate`. `PlayerController` is a Rigidbody2D controller (SmoothDamp velocity, coyote time, jump lockout, ground check via `OverlapCircleAll` on `m_WhatIsGround`, flip via negative `localScale.x`). It raycasts forward and sets `PlayerMovement._freezeLeft/_freezeRight` when facing an object tagged `Blockable` (used to show Idle instead of Run).
- `PlayerAnimationController` wraps the DragonBones `UnityArmatureComponent` (`Idle`, `IdleStraight`, `Run`, `Jump`, `Push`, `Pull`). Blacky has no Unity `Animator`; `PlayerMovement.anim` must stay typed as `PlayerAnimationController`.
- `PushableAndPullable` — hold `Fire1` to attach a `FixedJoint2D` to a box on `boxMask`; box mass is toggled 1 ↔ 500 (draggable vs. immovable). Not yet on the Blacky prefab.
- `Platform` — one component with a `PlatformType` enum (Moving / Appearing / Falling / Raising); fields shown per type via MyBox `[ConditionalField]`. Activated by setting `On`, typically from `SwitchTrigger`. Moving platforms parent the Player on collision.
- `KillZone` — trigger that restarts the level via `LevelChanger.LoadCurrentLevel()`. It reuses the GUID of the removed TB kit `GameManager`, which is how `GameManager.prefab` references it.
- `LevelChanger` — `DontDestroyOnLoad` singleton: `FadeToLevel(i)` fires the `FadeOut` animator trigger and the fade animation calls `OnFadeComplete()` via an animation event to `LoadScene`. `FadeToNextLevel()` advances by build index and wraps to 0. `LoadCurrentLevel()` reloads immediately.
- `fader` (on Whitey) — on Player trigger: fades to the next level, dissolves Whitey (`_Fade` on the Dissolve material) and freezes the player.
- `MenuController` / `MenuButton` / `AnimatorFunctionsPk` — keyboard-navigated menus. `GameManagerPk` — Escape pause menu with static `_isPaused` (checked by `PlayerMovement`); it compares the scene name to `"MainMenu"`, so don't rename that scene.
- `Prefabs/Systems/GameManager.prefab` (in every level) = `LevelChanger` + `KillZone` + pause menu UI. Scripts find it with `FindAnyObjectByType<LevelChanger>()`.

## Scenes and level flow

Build order (`ProjectSettings/EditorBuildSettings.asset`): `MainMenu`, `Sandbox`. Progression is by build index (`FadeToNextLevel`, `FadeToLevel(1)` for New Game, `FadeToLevel(0)` for the main menu), so reordering scenes changes gameplay flow.

## Conventions and gotchas

- Tags used by code: `Player`, `Blockable`. Layers: `Ground` (8), `Player` (9), `Platform` (10), `Pushable` (11), `Blockable` (12); physics queries depend on masks set in the Inspector (`m_WhatIsGround`, `boxMask`).
- Input uses the legacy `UnityEngine.Input` manager (planned move to the Input System for console support).
- Use Unity 6 APIs: `Rigidbody2D.linearVelocity` (not `velocity`), `bodyType` (not `isKinematic`), `FindAnyObjectByType` (not `FindObjectOfType`). Unity 6.5 turns several old APIs into compile *errors* (`GetInstanceID`, `Selection.activeInstanceID`, `EndNameEditAction`), and an error in any script puts the Editor in Safe Mode; MyBox, DragonBones and Foliage2D have been patched for this.
- Serialized field names (`m_JumpForce`, `_runSpeed`, `On`, etc.) are referenced by scene/prefab YAML — renaming them loses Inspector values unless you add `[FormerlySerializedAs]`.
- Behaviour wiring often lives in scene/prefab data (UnityEvents on buttons, animation events like `OnFadeComplete`), so grep `.unity`/`.prefab`/`.anim` files by script GUID (from the `.cs.meta`) or method name before removing anything. Always move assets together with their `.meta` files (`git mv` both) to keep GUIDs.
- Known broken references inherited from the old project: `Sandbox.unity` lighting settings asset, the sprite on `Prefabs/UI/WhiteFade.prefab`, and one clip in `Animations/UI/LoadingScreen.controller`.
